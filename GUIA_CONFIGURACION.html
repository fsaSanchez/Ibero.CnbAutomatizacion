2

Microsoft Graph API (Azure AD)

El sistema lee correos del buzón pui@ibero.mx usando la Microsoft Graph API con autenticación de aplicación (sin usuario interactivo). La configuración se divide en dos partes: registro de la app en Azure AD y restricción del acceso a solo ese buzón mediante Application Access Policy en Exchange Online.

Por qué se necesita Application Access Policy Microsoft Graph API solo permite pedir permisos de correo a nivel de tenant completo (Mail.Read = acceso a todos los buzones). No existe un permiso nativo de Azure AD para un solo buzón. Sin embargo, Exchange Online ofrece un mecanismo oficial para restringir ese permiso a un buzón específico mediante una política. El área de Seguridad puede auditar y verificar esta restricción con un solo comando.
Quién debe hacer esto Requiere dos roles: administrador de Azure AD (pasos 2.1) y administrador de Exchange Online (pasos 2.2). Pueden ser la misma persona o distintas.

2.1 Registro de aplicación en Azure AD

1
Iniciar sesión en Azure Portal

Ve a portal.azure.com e inicia sesión con tu cuenta institucional de administrador de Azure AD.

2
Crear el registro de aplicación

En el buscador escribe Registros de aplicaciones → + Nuevo registro.
Nombre: PUI-Ibero-Automatizacion
Tipo de cuenta: Solo cuentas de este directorio organizativo
URI de redirección: dejar vacío. Clic en Registrar.

3
Copiar los IDs

En la página de resumen, copia y guarda:
• Id. de aplicación (cliente) → ClientId
• Id. de directorio (inquilino) → TenantId

4
Crear el secreto de cliente

Certificados y secretos → Secretos de cliente → + Nuevo secreto de cliente.
Descripción: PUI-Secret | Caducidad: 24 meses.
Clic en Agregar y copia inmediatamente el Valor (solo visible una vez). Este es el ClientSecret.

5
Agregar permisos de API

Permisos de API → + Agregar un permiso → Microsoft Graph → Permisos de aplicación.
Agrega únicamente:

  • Mail.Read — leer correos
  • Mail.ReadWrite — marcar correos como leídos

Clic en Conceder consentimiento de administrador. Confirma.
Nota: estos permisos parecen globales, pero en el paso 2.2 los restringimos a solo pui@ibero.mx.

2.2 Restringir el acceso a solo pui@ibero.mx (Exchange Online)

Este es el paso clave para la aprobación del área de Seguridad. Se crea un grupo de seguridad con solo el buzón pui@ibero.mx y una política que impide que la app acceda a cualquier otro buzón.

6
Instalar el módulo de Exchange Online (si no está)

En PowerShell como administrador en cualquier equipo con acceso a internet:

Install-Module -Name ExchangeOnlineManagement -Scope CurrentUser -Force
7
Conectarse a Exchange Online 
Connect-ExchangeOnline -UserPrincipalName admin@ibero.mx

Se abrirá el navegador para autenticarse con la cuenta de administrador de Exchange.

8
Crear grupo de seguridad solo con el buzón PUI 
New-DistributionGroup `
  -Name "PUI-Buzon-Acceso" `
  -Alias "pui-buzon-acceso" `
  -Type Security `
  -Members "pui@ibero.mx"

Este grupo contendrá únicamente el buzón al que se permite el acceso.

9
Crear la política de restricción

Reemplaza <ClientId> con el valor copiado en el paso 3:

New-ApplicationAccessPolicy `
  -AppId "<ClientId-de-la-app>" `
  -PolicyScopeGroupId "pui-buzon-acceso" `
  -AccessRight RestrictAccess `
  -Description "PUI-Ibero: acceso restringido solo al buzon pui@ibero.mx"

RestrictAccess significa que la app solo puede acceder a los buzones dentro del grupo. Todo lo demás queda bloqueado automáticamente.

10
Verificar que la política funciona

Ejecuta estas dos pruebas. La primera debe devolver Granted, la segunda Denied:

# Debe devolver: Granted
Test-ApplicationAccessPolicy `
  -AppId "<ClientId>" `
  -Identity "pui@ibero.mx"

# Debe devolver: Denied (cualquier otro buzón)
Test-ApplicationAccessPolicy `
  -AppId "<ClientId>" `
  -Identity "rector@ibero.mx"

Estos comandos son la evidencia auditable que puedes presentar al área de Seguridad.

11
Desconectarse 
Disconnect-ExchangeOnline -Confirm:$false
Resultado esperado Al finalizar tendrás 3 valores para appsettings: TenantId, ClientId y ClientSecret. La política de Exchange garantiza que, aunque el permiso de Azure AD sea amplio técnicamente, en la práctica la app solo puede leer el buzón pui@ibero.mx y ningún otro. Esto es auditable y reversible en cualquier momento.
El backend no requiere ningún cambio La restricción opera completamente del lado de Microsoft. El código ya está preparado para trabajar con este esquema sin modificaciones.

Meta Graph API (Facebook Page)

El sistema publica alertas en la página de Facebook del CNB-Ibero usando la Meta Graph API. Necesitas un Page Access Token de larga duración y el Page ID.

Quién debe hacer esto Necesitas ser administrador de la página de Facebook del CNB-Ibero y tener acceso a Meta for Developers.

3.1 Crear la aplicación en Meta for Developers

1
Ir a Meta for Developers

Entra a developers.facebook.com con la cuenta de Facebook del administrador de la página.

2
Crear nueva app

Clic en Mis apps → Crear app. Selecciona el tipo Business. Nombre: PUI-Ibero. Vincula tu cuenta de negocio de Meta si aplica.

3
Agregar el producto "Pages API"

En el panel de la app, ve a Agregar productos y agrega Facebook Login for Business (o simplemente Pages API dependiendo de la versión del portal).

3.2 Obtener el Page ID

1
Buscar el ID de la página

Ve a la página de Facebook del CNB-Ibero. En el menú de la página (los tres puntos), selecciona Acerca de. Desplázate hasta el final para ver el ID de página. También puedes encontrarlo en Configuración de la página → Información de la página.

3.3 Generar el Page Access Token

1
Abrir el Explorador de la API Graph

Ve a developers.facebook.com/tools/explorer. Selecciona tu aplicación en el menú desplegable superior derecho.

2
Generar token de usuario

Clic en Generate Access Token. Selecciona los permisos:
pages_show_list, pages_read_engagement, pages_manage_posts, publish_to_groups (si aplica).

3
Obtener token de página

Con el token de usuario activo, haz esta petición en el explorador:

GET /me/accounts

La respuesta mostrará las páginas administradas. Copia el access_token correspondiente a la página del CNB-Ibero. Este es el Page Access Token de corta duración.

4
Convertir a token de larga duración (60 días)

Abre esta URL en el navegador (reemplaza los valores):

https://graph.facebook.com/oauth/access_token
  ?grant_type=fb_exchange_token
  &client_id={APP_ID}
  &client_secret={APP_SECRET}
  &fb_exchange_token={PAGE_ACCESS_TOKEN_CORTO}

El access_token en la respuesta JSON dura 60 días. Úsalo como AccessToken en appsettings.

5
Verificar el token

En el Explorador de la API Graph, usa Información del token (ícono de información junto al token) para confirmar que el token tiene los permisos correctos y la fecha de caducidad esperada.

El token expira cada 60 días Debes renovarlo manualmente antes de que caduque. Ver la sección 12 (Mantenimiento) para el procedimiento de renovación.

Base de datos SQL Server

El esquema de base de datos debe existir antes de arrancar la aplicación. El sistema usa EF Core con un contexto ya scaffoldeado — no hay migraciones automáticas; el script SQL se aplica manualmente.

1
Crear la base de datos

Abre SQL Server Management Studio (SSMS) y conéctate a localhost\SQLEXPRESS. Ejecuta:

CREATE DATABASE CNB_Ibero;
GO
2
Aplicar el script de esquema

Solicita al equipo el script SQL del proyecto (archivo schema.sql). Ábrelo en SSMS con la base de datos CNB_Ibero seleccionada y ejecútalo. El script crea los esquemas operacion, bitacoras y catalogos con todas sus tablas, vistas e índices.

3
Verificar la conexión

Desde el servidor donde correrá la API, abre PowerShell y ejecuta:

Test-NetConnection -ComputerName localhost -Port 1433

Debe responder TcpTestSucceeded: True.

4
Verificar Hangfire storage

Hangfire crea sus propias tablas automáticamente al arrancar la API por primera vez. No requiere acción manual adicional.

Autenticación Windows (Integrated Security) La cadena de conexión usa Integrated Security=True. El usuario de Windows bajo el cual corre el Application Pool de IIS debe tener permisos db_owner (o al menos db_datareader + db_datawriter) en la base de datos CNB_Ibero.

Archivo appsettings.json

Una vez que tienes todos los valores de los pasos anteriores, completa el archivo appsettings.json de la API. Ubícalo en:

C:\inetpub\wwwroot\pui-api\appsettings.json

El archivo completo debe quedar así (reemplaza los valores entre <>):

{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost\\SQLEXPRESS;Database=CNB_Ibero;Integrated Security=True;TrustServerCertificate=True;"
  },
  "Jwt": {
    "Key": "<clave-segura-de-al-menos-32-caracteres>"
    // Ver sección 8 para generar esta clave
  },
  "MicrosoftGraph": {
    "TenantId":     "<tenant-id-de-azure>",
    "ClientId":     "<client-id-de-azure>",
    "ClientSecret": "<client-secret-de-azure>",
    "Buzon":        "pui@ibero.mx"
  },
  "Facebook": {
    "PageId":      "<id-de-la-pagina-de-facebook>",
    "AccessToken": "<page-access-token-de-larga-duracion>"
  },
  "Hangfire": {
    "IngestaIntervalMinutos":         5,
    "ReintentoDatosIncompletosHoras": 4,
    "PublicacionHoraUtc":             14
    // 14 UTC = 8:00 CST (hora Ciudad de México en invierno)
  },
  "OpenAI": {
    "ApiKey": "<api-key-de-openai>",
    "Model":  "gpt-4o-mini"
  },
  "Logging": {
    "LogLevel": {
      "Default":             "Information",
      "Microsoft.AspNetCore": "Warning",
      "Hangfire":            "Information"
    }
  }
}
OpenAI API Key Crea una cuenta en platform.openai.com → API Keys → Create new secret key. El sistema usa el modelo gpt-4o-mini solo como fallback cuando la extracción por Regex no es suficiente.

Carpetas de almacenamiento en disco

El sistema guarda PDFs y fotos en disco local. Crea las carpetas y asigna los permisos correctos antes de arrancar la API.

1
Crear las carpetas

Abre PowerShell como administrador en el servidor y ejecuta:

New-Item -ItemType Directory -Force -Path "C:\Datos\PUI\PDFs"
New-Item -ItemType Directory -Force -Path "C:\Datos\PUI\Fotos"
2
Asignar permisos al usuario del Application Pool

El Application Pool de IIS corre bajo una identidad (por defecto IIS AppPool\pui-api). Ese usuario necesita escritura en estas carpetas:

$user = "IIS AppPool\pui-api"
icacls "C:\Datos\PUI" /grant "${user}:(OI)(CI)F" /T

Reemplaza pui-api con el nombre exacto de tu Application Pool.

3
Verificar

Confirma que la estructura existe:

Get-ChildItem C:\Datos\PUI

Debes ver las carpetas PDFs y Fotos.

8

Clave JWT segura

El archivo actual trae una clave de desarrollo temporal. Debes reemplazarla antes de producción. La clave debe tener al menos 32 caracteres aleatorios.

1
Generar la clave con PowerShell 
$bytes = New-Object byte[] 48
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
[Convert]::ToBase64String($bytes)

Copia el resultado (será algo como abc123.../xYz==). Ese es tu Jwt:Key.

2
Guardar la clave de forma segura

Guarda esta clave en el gestor de contraseñas institucional (LastPass, 1Password, Bitwarden o KeePass). Si se pierde, todos los tokens JWT activos dejarán de funcionar.

No compartir ni versionar esta clave La clave JWT nunca debe estar en el repositorio Git ni enviarse por correo o chat. Solo debe existir en el servidor de producción y en el gestor de contraseñas.

Despliegue en IIS — API .NET

9.1 Publicar la aplicación

Desde la máquina de desarrollo, ejecuta en la carpeta raíz del proyecto:

dotnet publish Ibero.CnbAutomatizacion.API\Ibero.CnbAutomatizacion.API.csproj ^
  --configuration Release ^
  --output C:\publish\pui-api

Copia el contenido de C:\publish\pui-api al servidor en C:\inetpub\wwwroot\pui-api\.

9.2 Crear el Application Pool

1
Abrir el Administrador de IIS

En el servidor, abre Administrador de Internet Information Services (IIS). En el panel izquierdo, ve a Grupos de aplicaciones.

2
Crear nuevo Application Pool

Clic derecho → Agregar grupo de aplicaciones.
Nombre: pui-api
Versión de .NET CLR: Sin código administrado (ASP.NET Core se autogestiona)
Modo de canalización administrada: Integrado

3
Crear el sitio web

En Sitios → clic derecho → Agregar sitio web.
Nombre: pui-api
Grupo de aplicaciones: pui-api
Ruta física: C:\inetpub\wwwroot\pui-api
Puerto: 5000 (o el que corresponda)

4
Verificar web.config

En la carpeta publicada debe existir un archivo web.config generado automáticamente por .NET con el handler de ASP.NET Core. Si no existe, créalo con este contenido mínimo:

<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <handlers>
      <add name="aspNetCore" path="*" verb="*"
           modules="AspNetCoreModuleV2"
           resourceType="Unspecified" />
    </handlers>
    <aspNetCore processPath="dotnet"
                arguments=".\Ibero.CnbAutomatizacion.API.dll"
                stdoutLogEnabled="true"
                stdoutLogFile=".\logs\stdout"
                hostingModel="inprocess" />
  </system.webServer>
</configuration>
5
Crear carpeta de logs 
New-Item -ItemType Directory -Force -Path "C:\inetpub\wwwroot\pui-api\logs"
icacls "C:\inetpub\wwwroot\pui-api\logs" /grant "IIS AppPool\pui-api:(OI)(CI)F"
6
Iniciar el sitio y verificar

En IIS, selecciona el sitio pui-api y clic en Examinar *:5000 (http). Debe responder con un JSON {"success":false} o similar. También verifica http://localhost:5000/scalar para ver la documentación de la API.

Despliegue en IIS — Portal React

10.1 Configurar la URL de la API

Antes de compilar, crea el archivo .env.production en la carpeta FrontReactCNB/portal-cnbIbero/:

VITE_API_URL=http://<ip-o-dominio-del-servidor>:5000

10.2 Compilar el portal

Desde la máquina de desarrollo, en la carpeta portal-cnbIbero:

npm install
npm run build

Esto genera la carpeta dist/. Copia su contenido al servidor en C:\inetpub\wwwroot\pui-portal\.

10.3 Crear el sitio en IIS

1
Agregar sitio web

En IIS: Sitios → Agregar sitio web.
Nombre: pui-portal
Grupo de aplicaciones: puedes usar DefaultAppPool (es HTML/JS estático)
Ruta física: C:\inetpub\wwwroot\pui-portal
Puerto: 80 (o 443 con SSL)

2
Configurar URL Rewrite para SPA

React Router necesita que todas las rutas desconocidas regresen index.html. Instala el módulo URL Rewrite de IIS (descargable desde iis.net) y crea el archivo web.config en C:\inetpub\wwwroot\pui-portal\:

<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="SPA Routes" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGrouping="MatchAll">
            <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          </conditions>
          <action type="Rewrite" url="/index.html" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>

Mantenimiento y renovación de tokens

Token de Facebook (cada 60 días)

El Page Access Token de Facebook expira aproximadamente cada 60 días. Programa un recordatorio para renovarlo antes de que caduque.

1
Verificar la caducidad del token actual

Ve al Explorador de la API Graph (developers.facebook.com/tools/explorer), pega el token actual en el campo y usa Información del token para ver la fecha de expiración.

2
Generar nuevo token de larga duración

Repite el proceso de la sección 3.3 (pasos 1 al 4) para obtener un nuevo token.

3
Actualizar appsettings.json en el servidor

Edita el archivo en C:\inetpub\wwwroot\pui-api\appsettings.json y reemplaza el valor de Facebook.AccessToken. Después, reinicia el Application Pool:

Restart-WebAppPool -Name "pui-api"

Secreto de Azure AD (cada 24 meses)

1
Generar nuevo secreto

En el portal de Azure, ve al registro de la aplicación PUI-Ibero-Automatizacion → Certificados y secretos → agrega un nuevo secreto antes de que caduque el actual.

2
Actualizar appsettings y reiniciar

Igual que con el token de Facebook: actualiza MicrosoftGraph.ClientSecret y reinicia el Application Pool.
